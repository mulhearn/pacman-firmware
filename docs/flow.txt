Basic work flows for pacman project
===================================

The flows assume you have setup Vivado, e.g. via:

> source /tools/Xilinx/Vivado/2023.2/settings64.sh

and that you are starting each section from root directory of the repository, i.e. pacman-firmware/

At top-level, the project is organized as follows:

ghdl/
   This is where HDL is developed and validated via GHDL, independently of vendor tools.

vivado/tcl/
   This is where top-level TCL scripts for project creation, and running synthesis, etc.

vivado/src/bd/hw1v5/zsys.tcl
    This is where the top level board design file (generated by Vivado) is stored for PACMAN 1v5.
    Each supported HW version has it's own top level board design.

vivado/src/hdl/
    Custom HDL for the Vivado project.

vivado/src/constraints/
    Constraints for the Vivado project.

products/pacman.xsa
     The hardware export file.

reports
     Various reports from the most recent build.

Building the firmware for PACMAN v 1.5:
---------------------------------------

create the project from tcl, note that you specify target PACMAN HW version here (and only here):

> cd vivado
> vivado -mode batch -source tcl/create.tcl -tclargs hw1v5

run systhesis, implementation, and write bit stream (SIB):

> vivado -mode batch -source tcl/runsib.tcl
> cd ..

The hardware export file produced by this flow is created at:

products/pacman.xsa

If you need to reproduce the hardware export file without rebuilding the whole project, you can use:

> vivado -mode batch -source tcl/hardware.tcl 

Various reports from the latest firmware build are stored in:

reports/*.txt

Building the firwmare for a different hardware version:
-------------------------------------------------------

Supported PACMAN hardware version can be seen via:

ls vivado/src/bd

If you want to build the firmware for a different (supported) hardware
version, you simply change the tag at project creation:

> cd vivado 
> vivado -mode batch -source tcl/create.tcl -tclargs hw1v4
> cd ..

Accessing the project with the Vivado GUI:
------------------------------------------

Once you have created the project as describe above, you may access it
via the Vivado GUI:

> cd vivado
> vivado pacman-fw/pacman-fw.xpr
> cd ..


Contributing HDL code to the project:
-------------------------------------

Custom HDL for the project does not depend on vendor IP, and can be
analyzed, elaborated, and run using GHDL.  Every HDL module xxx.vhd
has a testbench tb/xxx_tb.vhd which validates the module at least to
the level of initial hardware checkout.

For example, to validate the HDL for the TX unit:

> cd ghdl/tx/
> make
> make run-testbenches 
> make run-unit-testbench 
> cd ../..

Once HDL code is validated with GHDL, it is imported to the Vivado
source tree via:

> ./utils/sync_ghdl.sh

To get the update HDL into the vivado project, first blow away the existing project:

> cd vivado
> rm -fr pacman-fw

Then create a new project, which will automatically import the updated files:

> vivado -mode batch -source tcl/create.tcl -tclargs hw1v5
> cd ..

Making changes to the Vivado Board Design:
------------------------------------------

The Vivado project is a *product* of this repository.  For the amateur
firmware developers on the team, this is a good compromise: we can
still poke around at the project via the GUI, but the finished product
can be reliably built directly from sources in the repository using
only TCL.  We *DO NOT* use make project from TCL feature, which is far
too non-deterministic to be useful.  Instead, we export the top-level
block design (zsys.bd) and build the project from custom tcl scripts
as shown above.  The project code is arranged into units
(e.g. tx_unit.vhd) each with a stable interface, so changes via the
GUI are rarely needed.

If you need to make changes to the top-level board design:

cd vivado
vivado pacman-fw/pacman-fw.xpr

Then in the vivado GUI:
 - make your changes as needed
 - File -> Export -> Export Block Design

Then move the block design file into the correct location for your
target HW, so that it is used for the next project creation:

> cp pacman-fw/zsys.tcl ./src/bd/hw1v5/zsys.tcl
 
At this point, it is a good idea to blow away (or move!) the project
directory, and confirm that it recreated successfully via the project
creation tcl file.
